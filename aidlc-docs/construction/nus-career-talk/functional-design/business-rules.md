# Business Rules and Constraints

## Content and learning

Use Vietnamese for explanations and controls, with official English field names and recognisable career titles. Explain new vocabulary, include CS/CE overlap and ground NUS degree/focus claims in official references. Exactly eleven areas have complete content and demos. At least two career examples per field are possibilities, not guarantees. Do not invent endorsements, speaker anecdotes, admissions or salary claims.

All main scenes have one primary idea. A map gives complete overview without requiring eleven live demonstrations. The closing includes a reflection, an achievable school-problem project, exploration and references.

## Session and navigation

Only valid area and slide IDs are accepted. Previous/next never wraps. Exploration preserves presentation position; selection does not create extra live slides. No internal demo action changes the URL, writes portfolio preferences or advances the narrative. Direct route entry starts at opening; returning to a talk after leaving may start a new visit. The explicit return action uses a recognised local section/journal hash, otherwise #home; browser back/forward remains authoritative.

Only route-boundary transitions update history. The App route recogniser matches `#/talks/nus-cs` exactly. Existing unknown-route behaviour stays with the portfolio. The talk has no server endpoints and no student-data persistence.

## Demo validation and failures

All numerical controls have finite bounded values and defined discrete options. Out-of-range or malformed action payloads retain prior valid state; do not compute NaN results. Every demo uses deterministic local data. Inputs clear stale results as defined in the model. Run/step/reset are bounded and repeatable. Explain no-route and failed-test states visibly; these are learning outcomes rather than crashes.

The security demo labels its weak encoding explicitly; no real secret entry is requested. Expression examples are fixed and never evaluated as executable input. Retrieval scores use the stated colour-only criterion. Parallel timing uses ideal model units and exposes the no-overhead assumption. Test/release progress requires a passing current run.

## Browser and accessibility rules

Motion preference and manual pause combine so either can stop continuous motion. Pausing does not remove explanations or prevent explicit exploration actions. Controls keep semantic labels and text equivalents. Fullscreen rejection/absence leaves normal view working. Focus moves only for meaningful scene/view/topic transitions, not on every slider value or model frame. User input shortcuts take precedence over presentation shortcuts.

## Verification obligations

Verify each M01–M11 with known inputs and reset. Check narrative boundaries, view/topic retention, source/content completeness, unsupported fullscreen, keyboard conflicts, both entry links and history/return behaviour. Projection readability and talk duration need human review/rehearsal. These are future checks; this design does not claim implementation results.
